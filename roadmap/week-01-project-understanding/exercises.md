# Week 01 Exercises: From Base Idea to Buildable Plan

## How to Use These Exercises

Complete these before the build task. Each exercise is small and beginner-focused. Save outputs in `docs/evidence/week-01/exercises/`.

Do not inspect the finished app code to answer these. Use your own reasoning from the product idea.

---

## Exercise 1: Explain the Product in Five Sentences

### Goal

Turn the base idea into a clear explanation.

### Task

Write five sentences:

1. Who the app is for.
2. What problem the app helps with.
3. What input the user gives.
4. What output the app returns.
5. Why this is a mobile app project.

### Output

File: `docs/evidence/week-01/exercises/exercise-01-product-explanation.md`

### Validation

- [ ] I used plain language.
- [ ] I did not mention advanced implementation details.
- [ ] Another beginner could understand the idea.

---

## Exercise 2: Write the Main User Journey

### Goal

Understand the product as a user flow before thinking about code.

### Task

Write the main journey as 6 to 10 steps.

Start with:

```text
1. User opens LeafGuard AI.
2. ...
```

End with the user seeing or saving the result.

### Output

File: `docs/evidence/week-01/exercises/exercise-02-user-journey.md`

### Validation

- [ ] The journey has a clear start and end.
- [ ] Each step describes user behavior or visible app behavior.
- [ ] The journey does not depend on code that has not been taught.

---

## Exercise 3: Make a Feature Card List

### Goal

Separate final-product features into learnable pieces.

### Task

Create a table with at least 8 feature cards.

Use this format:

| Feature | User Value | First Week Built | How to Validate Later |
|---|---|---:|---|
| Open app screens | User can navigate the app | 02 | App launches and screens open |

Suggested features:

- app screens
- camera input
- gallery input
- backend upload
- result display
- scan history
- disease library
- offline prediction
- share result
- notification reminder

### Output

File: `docs/evidence/week-01/exercises/exercise-03-feature-cards.md`

### Validation

- [ ] Every feature has user value.
- [ ] Every feature has a likely week.
- [ ] Validation is about behavior, not vague completion.

---

## Exercise 4: Draw a Rough Screen Map

### Goal

Imagine the app from the user's view.

### Task

Draw or list the screens the final app may need.

Minimum screens:

- Home
- Scan
- Result
- History
- Disease Library
- Settings or About

For each screen, write:

- purpose
- one main button or action
- what the user should see

### Output

File: `docs/evidence/week-01/exercises/exercise-04-screen-map.md` or `.png`

### Validation

- [ ] Each screen has one clear purpose.
- [ ] The screen list supports the main user journey.
- [ ] The screen map is not overloaded with technical class names.

---

## Exercise 5: Draw the Box-Level System Sketch

### Goal

Understand the system at a high level.

### Task

Draw a sketch with these boxes:

```text
User
Android App
Image Input
Backend / AI Service
Disease Result
Local History
Disease Library
Evidence Folder
```

Draw arrows showing how the user's image becomes a result.

### Output

File: `docs/evidence/week-01/exercises/exercise-05-system-sketch.md` or `.png`

### Validation

- [ ] The sketch has no more than 10 boxes.
- [ ] Arrows are labeled in plain language.
- [ ] It can be explained in under 2 minutes.

---

## Exercise 6: Make a Week Growth Table

### Goal

See how the final product grows gradually.

### Task

Create a 12-row table.

Use this format:

| Week | What I Learn | What the Product Gains | Validation Demo |
|---:|---|---|---|
| 01 | Product idea and journey | Foundation plan | Explain plan and evidence |
| 02 | Android screens | Runnable UI skeleton | Tap through screens |

Fill all 12 weeks using the roadmap names.

### Output

File: `docs/evidence/week-01/exercises/exercise-06-week-growth-table.md`

### Validation

- [ ] Each week adds something new.
- [ ] Each validation demo checks only that week's contribution.
- [ ] The table reaches a complete app by Week 12.

---

## Completion Rule

You may start `build-task.md` only after all six exercises exist and you can explain them without reading the finished app code.
