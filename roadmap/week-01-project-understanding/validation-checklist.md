# Week 01 Validation Checklist: Product Foundation

## Milestone Demo

> Demo: Explain the Week 01 foundation package from beginning to end: product idea -> user journey -> screen map -> system sketch -> 12-week growth map. This proves the first 5% of the product is complete.

You may not move to Week 02 until every required item is yes.

---

## How to Use This Checklist

For each item, answer yes or no. If the answer is no, fix it before moving on.

Save your completed checklist as:

```text
docs/evidence/week-01/week-01-validation.md
```

---

## 1. Product Idea

- [ ] `docs/evidence/week-01/product-idea.md` exists.
- [ ] It explains LeafGuard AI in one sentence.
- [ ] It identifies the target user.
- [ ] It explains the plant-disease problem in plain language.
- [ ] It explains why Android/mobile is useful for this problem.
- [ ] It lists what is in scope for the course.
- [ ] It lists what is out of scope for the course.
- [ ] It includes an honest limitation statement.
- [ ] It does not claim the app is already built.
- [ ] It does not require understanding final code.

Pass rule: all 10 items yes.

---

## 2. User Journey

- [ ] `docs/evidence/week-01/user-journey.md` exists.
- [ ] The journey starts with the user opening the app.
- [ ] The journey includes image input.
- [ ] The journey includes disease result display.
- [ ] The journey includes guidance such as symptoms, treatment, or prevention.
- [ ] The journey includes saving or reviewing a result later.
- [ ] Each step is written in beginner language.
- [ ] The journey can be explained in under 2 minutes.

Pass rule: all 8 items yes.

---

## 3. Screen Map

- [ ] `docs/evidence/week-01/screen-map.md` exists.
- [ ] Home screen idea is included.
- [ ] Scan screen idea is included.
- [ ] Result screen idea is included.
- [ ] History screen idea is included.
- [ ] Disease Library screen idea is included.
- [ ] Settings or About screen idea is included.
- [ ] Each screen has a user goal.
- [ ] Each screen has one main action.
- [ ] The map does not depend on memorizing final Activity class names.

Pass rule: all 10 items yes.

---

## 4. System Sketch

- [ ] `docs/evidence/week-01/system-sketch.md` or image file exists.
- [ ] It shows the User box.
- [ ] It shows the Android App box.
- [ ] It shows Image Input.
- [ ] It shows Detection Result.
- [ ] It shows Local History.
- [ ] It shows Disease Library.
- [ ] It shows Backend or AI Service as a future component.
- [ ] Arrows are labeled in plain language.
- [ ] It has no more than 10 boxes.
- [ ] It avoids detailed database, networking, or model internals.

Pass rule: all 11 items yes.

---

## 5. Week Growth Map

- [ ] `docs/evidence/week-01/week-growth-map.md` exists.
- [ ] It has rows for Weeks 01 through 12.
- [ ] Week 01 is described as product idea and learning foundation.
- [ ] Week 02 is described as Android UI skeleton or screens.
- [ ] Each week has a learning focus.
- [ ] Each week has a product increment.
- [ ] Each week has a validation demo.
- [ ] The demos validate weekly slices, not the entire future product too early.
- [ ] The map reaches a complete app by Week 12.

Pass rule: all 9 items yes.

## 6. Evidence Organization

- [ ] `docs/evidence/week-01/` exists.

## 7. Understanding Check

Can you explain these without reading final app code?

- [ ] Who is the target user?
- [ ] What problem does the app help solve?
- [ ] What is the main user journey?
- [ ] What screens might the app need?
- [ ] What does Week 01 contribute to the final product?
- [ ] What will Week 02 build first?
- [ ] Why should future weeks have their own validation demos?

Pass rule: all 7 items yes.

## Completion Criteria

Week 01 is complete only when:

1. All required sections above pass.
2. The milestone demo can be performed live.
3. Evidence is saved in `docs/evidence/week-01/`.
4. You can explain the foundation in your own words.
